# Схема доступа — 17.11.2026

Постановка: коллега создаёт публичную заявку, владелец подтверждает, GitHub Actions отправляет персональное приглашение. Без общего пароля и внешнего сервера. Подтверждение относится только к автору заявки, включает возможность пополнения закрытого репозитория.

## Границы доверия

Публичный portal agnstrv/plant-library-access, ID1461140644. Только владелец agnstrv ID148447292 может одобрить. Целевой private repository agnstrv/plant-texture-library, ID1461061556. Имена, ID и приватность проверяются; они не берутся из тела заявки.

Workflow запускается по issues:labeled и принимает только access-approved от владельца; скрипт повторяет проверку, получает свежую issue и последнее событие установки метки. Автор должен оставаться тем же GitHub User; PR и бот не принимаются. Отдельно проверяется инициатор повторного запуска. Правка произвольного текста не меняет получателя. Снятие одобрения до вызова API останавливает выдачу; отзыв после отправки — действие администратора библиотеки.

Токен репозитория заявок используется для чтения issue и публикации результата. Отдельный fine-grained PAT LIBRARY_INVITE_TOKEN имеет Administration write только для target library, хранится в Secrets и используется только для фиксированного GitHub API. Redirect запрещён. Ключ не выводится в логах и не передаётся коду заявителя. Third-party checkout закреплён полным SHA. PR-тесты не получают секрет приглашений. Только владелец имеет право записи в portal.

Чтение текущего состояния, проверка уже существующего доступа/приглашения и узкая сериализация по issue обеспечивают повторяемость. Успех — подтверждённый ответ GitHub на приглашение или доказанный существующий доступ; принятие пользователем не подменяется отправкой. Ошибка выдачи оставляет заявку открытой с access-error.

## План проверки

Локальные тесты API-моками: владелец/посторонний, снятая метка, подмена имени в тексте, чужой репозиторий, PR/бот, повтор запуска, отсутствующий secret, успешное приглашение, существующий доступ, ошибки API, защита секретов. Независимый read-only AI-review до публикации. Живой workflow tests и заявка владельца проверяют инфраструктуру без выдачи доступа третьим лицам. --check проверяет настроенный secret без приглашения; реальная выдача коллеге требует его будущей одобренной заявки.

## Границы

Для создания fine-grained PAT требуется действие владельца в настройках GitHub. Уже сохранённый широкий Git/OAuth-токен не переносится в публичный workflow. Administration write у GitHub шире одного метода приглашения; поэтому токен ограничен единственным репозиторием, доступ к portal на запись не выдаётся заявителям. При изменении владельца/переименовании аккаунта правила требуют явного обновления. Публичность заявки означает, что логин заявителя виден посетителям.
